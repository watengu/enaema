# エナエマ

## 🎯 目的・概要
赤文字ファッション誌の世界観で、日々の美容・ファッションタスクを
猫巫女獣人キャラと一緒に楽しく続けられるルーチン管理アプリ。

## 🌟 コアコンセプト・世界観
- 「雑誌を読みながらタスクをこなす」ような没入感
- キャラは相棒であり、達成を一緒に喜んでくれる存在
- 一人でやってる感じがしない、緩いソーシャルのライブ感
- girls concierge / 赤文字ファッション誌路線（上品・大人可愛い）

## 権限・機能差分

### ノーログイン
- シチュエーション選択：基本4つ（朝・昼・晩・寝る前）
- デフォルトタスク：各シチュエーション先頭3つ
- パーソナルカラー・骨格・顔タイプ選択可能
- ソーシャル機能はサンプル表示のみ

### 無料ログイン
- シチュエーション選択：基本4つ＋将来追加分（デート前・休日など）
- デフォルトタスク：各シチュエーション5つ
- キャラ：猫巫女獣人（ワード・コマンド反応、放置連動の育成要素）
- パーソナルカラー・骨格・顔タイプ＋キャラ選択
- ソーシャル機能フル利用可能

### 有料ログイン（将来）
- キャラのカスタム・変更可能（清楚・ギャル・クールなど）
- 限定シチュエーション（デート前など）の先行/専用解放の可能性
- テーマ切り替え（elegant / sparkle など）の可能性

## コア機能

### タスク・ルーチン
- 記事風レイアウトで表示（ホーム画面と同一）
- デフォルト項目をポップアップから選択してセット
- 「新規セット」「前回の続き」「やり直し」の3ボタン
- やり直し時はタイムラインに流れる
- ドラッグ＆ドロップは初期非対応（長押し並べ替え or 上下ボタン）
- 設計思想：チェックボックス式の「達成管理」ではなく、「見る・浸る・
  変更する」記事的な体験を意図的に採用している。この設計はリテンション
  （アプリを開く理由）をキャラの反応・ライブ感・実績演出に強く依存させる
  トレードオフを伴う。実装時はキャラ反応（trigger_type別画像）と
  ソーシャル機能のライブ感の質を優先度高く磨くこと
- 画面構成イメージ（雑誌の特集記事風。詳細はDESIGN.md参照）：
  罫線で囲んだ見出しボックス（例:「朝のルーチン」）→ タスク項目を
  バッジ化・カード化せず記事の箇条書きのように縦に並べる → 隅に
  小さく進捗（例:2/5）を控えめに表示。カラフルな付箋型バッジの多用や
  手書き風装飾の散りばめは採用しない

### デフォルトタスク例
シチュエーションはマスタ管理とし、今後追加可能（詳細はASSETS.md参照）
各シチュエーション5タスク×専用キャラ画像（1タスク1画像、計20枚＋ホームメイン1枚）

**朝**：白湯 / 洗顔 / 化粧水 / 乳液 / 下地・メイク
**昼**：皮脂・崩れオフ / あぶらとり・ミスト / リップ直し / 水分補給 / 姿勢・軽ストレッチ
**晩**：クレンジング / 洗顔 / 化粧水 / 美容液 / 乳液・クリーム
**寝る前**：ヘアケア / ハンドクリーム / リップケア / ストレッチ・深呼吸 / 翌日の服チェック

### ソーシャル機能（ハイブリッド仕様）

**タイムライン（X風）**
- タスクセット・やり直し投稿が流れる
- 対象：ログイン時刻の前後1時間以内にセットした他ユーザー（同じ時間帯優先）
- 投稿から3時間で自動削除
- 最大表示件数：20件程度
- オフピーク時は対象範囲を自動で広げる（前後1時間→2時間など）
- それでもユーザー数が枯渇する場合の最終フォールバック：直近で活動した
  別時間帯のユーザーの投稿を「薄く」（例：不透明度を下げる、
  「別の時間帯の投稿」であることが分かる控えめな表示にする）混ぜて
  空白を避ける。完全に空の画面にはしない

**右下透過コメント（TikTok風）**
- 他ユーザーのルーチン（キャラスタンプ付き）が透過で流れる
- 優先：同じ時間帯で現在ログイン中（オンライン）のユーザー
- オンラインが少ない場合：前後1時間以内にセットしたユーザーも表示
- 同時表示最大3〜5件
- 1時間で自動削除、または新着投稿で古いものから押し出す方式
- 個別非表示可能

**ニコニコ風スクロール**
- 天気・服装指数・トレンド情報（美容/ファッション/グルメ）・おしゃれ特集・ニュースが小さく流れる
- 情報種別ごとに簡易アイコン表示
- 非表示機能あり
- 将来：情報収集アプリで自動収集したネタと連携

### ソーシャル機能の安全設計
- 投稿ごとに公開/非公開を選択可能（デフォルト公開）
- 特定ユーザーをブロック可能（ブロックすると双方の投稿が非表示になる）
- 表示名はニックネーム/キャラ名のみ、本名・メールアドレスは非表示

### キャラ
- 位置：ファッション誌のモデルのように画面の目立つ位置に配置
- 無料：猫巫女獣人（反応・放置連動）
- 有料：カスタム可能
- 将来：獣人シリーズなど他キャラ追加、季節限定衣装の可能性
- ビジュアルはアプリの性質上、露出を抑えた和装アレンジで安全に調整

### その他
- 3日坊主クリア・7日ログインは連続不要（累計でOK）
- 達成で場面追加（ストーリー要素、ラノベ本編との連動も視野）
- フッターメニュー：[ホーム(タスク込み)] [タイムライン] [マイページ(キャラ込み)]

## 🔮 将来検討事項（MVP対象外）
- 「紹介つながり」機能：招待制で1対1/グループ接続し、許可制でスタンプ・
  デフォルトワードを個別にやりとりできる機能（詳細仕様は未確定）
- 「放置中キャラの自動つながり」機能（アイデア段階）：
  - タスク・ルーチンのタイミングが合う他ユーザーと自動でゆるく接続し、
    キャラ同士が勝手にスタンプでやりとりする演出
  - 「紹介つながり」とは別ベクトル（招待制ではなく自動マッチング）
  - 通知は出さず、マイページ等でそっと見える程度のさりげない演出
  - ユーザー側で繋がりのオン/オフを切り替え可能にする
  - ユーザーが一定期間タスクを継続しなければ、繋がりは自動的に消える
  - blocksテーブルとの整合（ブロック関係は自動接続の対象外にする）を
    実装時に必ず考慮する
- ソーシャル機能の「行動力（エネルギー）制」導入（アイデア段階）：
  - タイムライン投稿・透過コメントへのリアクション等、ソーシャル機能側
    のみに1日の利用回数上限を設ける案（タスク・ルーチン機能自体には
    行動制限をかけない。継続支援という本アプリの目的と矛盾するため）
  - 無料は1日分の行動力、追加は課金または友達招待で回復
  - 招待による行動力回復は「紹介つながり」機能の特典としても転用可
  - 月額パス（行動力増加・広告オフ等）の形での将来課金導線とも相性が良い
  - 導入する場合、行動力切れのタイミングが「継続を妨げるストレス」に
    ならないよう、タスク達成そのものは絶対に制限しない設計を厳守する
- シチュエーション追加：デート前・休日・季節性タスクなど
- キャラ追加・季節限定衣装
- バッジ/称号システム、賑わい可視化（「今の時間帯◯人活動中」等）
- 情報収集アプリとの自動連携（ニコニコスクロールへのネタ自動流し込み）
- sparkleテーマなど複数テーマ対応
- Supabaseマイグレーションの自動化、E2Eテスト
- Stripe決済、Google/Apple等ソーシャルログイン、PayPal/PayPay対応
- リワード広告（ネイティブアプリ化を検討する場合）

## 🛠️ 使用技術

- Backend/DB/Auth: Supabase（RLS必須）
- デプロイ: Vercel
- リポジトリ: GitHub
- 開発環境: GitHub Codespaces + Aider
- CI: GitHub Actions（PR時にbuild + lint）
